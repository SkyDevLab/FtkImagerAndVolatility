THE BASICS

First, understand the big picture

Two tools, two jobs.

💾

FTK Imager

In this lab, FTK Imager is used to acquire physical memory and create the RAM evidence file.

  • Capture RAM
  • Create a memory image
  • Support evidence preservation
  • Calculate or document hashes
🐼 Think of FTK Imager as the camera. It captures a snapshot of RAM.
🧠

Volatility 3

Volatility analyzes the memory image and reconstructs useful operating-system information.

  • System and kernel information
  • Processes and process trees
  • Command-line arguments
  • Network artifacts
🎋 Think of Volatility as the detective. It examines the snapshot.
WHY EXAMINE RAM?

Memory can show the system's state at capture time

EVIDENCE INTEGRITY

SHA-256 is a fingerprint, not encryption

The same file contents produce the same SHA-256 hash.

memdump.mem
→
SHA-256
→
64-hex-character fingerprint
PowerShell
Get-FileHash "memdump.mem" -Algorithm SHA256
Why re-verify?

Hash the same evidence file again later and compare it with the recorded baseline. A match indicates the file contents were unchanged between those checks.

VOLATILITY 3

Commands you'll actually use

Replace the example filename/path with your actual memory image.

01windows.info

System/kernel context. A useful first validation step.

vol -f "memdump.mem" windows.info

02windows.pslist

Lists processes from the active Windows process structures.

vol -f "memdump.mem" windows.pslist

03windows.pstree

Shows parent-child process relationships.

vol -f "memdump.mem" windows.pstree

04windows.psscan

Scans memory for process structures, including artifacts that may no longer be in the active list.

vol -f "memdump.mem" windows.psscan

05windows.cmdline

Shows command-line arguments associated with processes.

vol -f "memdump.mem" windows.cmdline

06windows.netscan

Examines memory for network connection structures.

vol -f "memdump.mem" windows.netscan
PROCESS FORENSICS

pslist vs psscan

The key idea behind the hidden-process scenario.

📋

pslist

Looks at Windows' active process listing.

Think: “What's currently linked?”
VS
🔎

psscan

Scans memory for process structures that look like _EPROCESS objects.

Think: “What process artifacts are present?”
⚠️

Important: A PID found by psscan but not pslist is not automatically malware. It may be a terminated process or another artifact that needs further validation.

pslist

1000 explorer.exe2000 chrome.exe3000 powershell.exeCount: 3

psscan

1000 explorer.exe2000 chrome.exe3000 powershell.exe4000 cmd.exe ⚠️Count: 4
Mismatched PID: 4000 — investigate it; don't jump straight to a malicious verdict.

FAQ

Questions beginners usually ask

What is the difference between FTK Imager and Volatility?

FTK Imager can acquire RAM for this workflow; Volatility analyzes the resulting memory image.

Is SHA-256 encryption?

No. SHA-256 is a cryptographic hash function that produces a fixed-size fingerprint of input data.

Will the SHA-256 hash stay the same?

Yes, for the exact same file contents. Change the file contents and the hash should change.

Why can psscan return more processes than pslist?

Because psscan scans memory for process structures, while pslist follows the active process listing. Some artifacts may remain after a process is no longer active.

Does a mismatched PID mean malware?

No. It is an investigation lead, not a conclusion. Validate the process with additional evidence.

Why run windows.info first?

It helps establish the operating-system and kernel context needed for later Windows plugins.

What does pstree tell me?

It helps show parent-child process relationships and process creation chains.

What should I do if a plugin fails?

Stop before inventing results. Diagnose the memory image, symbols, plugin compatibility and acquisition details first.
